# 国内直连与 NSS 加速验收条件

用户要求：国内连接不经过 Sing-box，国外需要代理的连接由 Sing-box 处理；合适的国内转发连接应实际进入 NSS/ECM 加速路径。现用系统已配置国内 IP 绕过防火墙透明代理，并在 Sing-box 内使用国内域名/IP 直连规则。此处只记录旧配置和 V4 验收目标，不宣称旧机或 V4 的每条流都已硬件加速。

## 必须补齐的后端

1. 从同一版本的 `geoip-cn.srs` 生成供 nftables 使用的国内 IPv4 CIDR 列表，或选择可追溯的同源 JSON。旧更新脚本只下载 `.srs`，旧防火墙却读取 `.json`；在新系统上更新规则时要原子替换、校验至少 5000 条有效网段并在失败时保留上一版。`geosite-cn.srs` 等域名规则仍供 Sing-box 和 DNS 使用，不能用 IP 表代替域名策略。
2. 让国内 IP 在 TCP 和 UDP 透明代理规则之前放行；按旧语义处理 DNS、局域网地址和 IPv6。确认域名解析、国外站点落在国内 CDN 地址等交叉情形的预期策略。
3. 完成 firewall4 安装/删除、`fw4 check`、重载恢复、TPROXY 的策略路由与回滚。候选 nft 规则须保留 `0x66/0xff` 之外的现有标记位；离线工具可筛查 `166` 表、现有 ip rule 与 mwan3 掩码冲突，但不批准启用。在 WAN 切换后重建必要状态并实测流量。
4. 在 V4 实机上分别测国内直连和国外代理。记录实际入口/出口、Sing-box 连接与防火墙规则计数，确认国内连接没有进入代理监听端口；再用该 NSS/ECM 构建实际暴露的计数器或连接状态验证国内连接加速。仅看到模块加载、吞吐较高或软件 flowtable `[OFFLOAD]` 都不足以证明 NSS 硬件加速。

## 验收流量

| 场景 | 必须观察到的结果 |
| --- | --- |
| 国内 IPv4 网站，TCP 与 UDP | 直连、未触发 Sing-box、符合条件的连接可见 NSS/ECM 加速证据 |
| 国外代理网站，TCP 与 UDP | 命中透明代理；出口与节点策略一致；不会误进直连加速 |
| 国内域名解析到境外地址、国外域名解析到国内 CDN | 行为符合事先选定的域名/IP 优先级，DNS 与路由结果一致 |
| 双 WAN 比例、单线故障与恢复 | 国内直连和国外代理各自按策略切换，标记和回程不串线 |
| IPv6、规则更新失败及服务重启 | 不绕过所选策略；保留可用旧规则，错误时能回滚 |

验收先使用测试固件和测试设备。首次 4.4→6.12 的网页刷机仍受独立恢复门禁阻断。
